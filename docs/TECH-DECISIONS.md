# প্রযুক্তি-সিদ্ধান্ত: কেন এই স্ট্যাক

## বর্তমান স্ট্যাক

প্লেইন HTML + CSS + JavaScript (ক্যানভাস), বিল্ড ধাপ নেই, কোনো নির্ভরতা নেই; Cloudflare-এ স্ট্যাটিক ফাইল হিসেবে; PWA।

## কেন এটা এই প্রজেক্টের জন্য উপযুক্ত

- একটাই কাজ (ছবি + নাম → ফ্রেম), একটাই পেজ। ফ্রেমওয়ার্ক যোগ করলে ডাউনলোড-সাইজ ও জটিলতা বাড়ে, লাভ কম।
- ৯৮% ব্যবহারকারী মোবাইলে, অনেকে সস্তা ফোনে; কোড ছোট ও দ্রুত।
- ডিপ্লয় সহজ: ফোল্ডার আপলোড বা `git push`, বিল্ড ফেইলের ঝুঁকি নেই।
- মূল কাজ ক্যানভাস-রেন্ডারিং, যেটা কোনো UI ফ্রেমওয়ার্ক সহজ করে না।

## দুর্বলতা (সৎভাবে)

| সমস্যা | প্রভাব |
|---|---|
| জেএস ফাইলগুলো একই গ্লোবাল স্কোপে, ক্রমের উপর নির্ভরশীল | ফাইল সরালে/ক্রম বদলালে ভাঙে |
| টাইপ নেই, অটো টেস্ট নেই | বদলানোর পর হাতে টেস্ট করতে হয় |
| SW-এর `PRECACHE` তালিকা ও `VERSION` হাতে বদলাতে হয় | ভুলে গেলে ইউজার পুরনো সংস্করণ দেখে |
| ফাইলের নামে হ্যাশ নেই | ক্যাশ নিয়ে সতর্ক থাকতে হয় |
| ফ্রেমের জ্যামিতি হাতে মাপা | নতুন ডিজাইনে মাপ বসাতে হয় (`prepare-frame.py` কিছুটা সাহায্য করে) |

## সিদ্ধান্ত

- **এই মাহফিলের জন্য: এটাই যথেষ্ট ও সঠিক।** বদলানোর দরকার নেই।
- **যদি প্রতি বছর বা একাধিক মাদরাসার জন্য পুনর্ব্যবহার করতে চান**, তখন ধাপে ধাপে বদলান:
  1. **Vite + TypeScript** (ES মডিউল): গ্লোবাল স্কোপ সমস্যা, টাইপ সমস্যা যায়।
  2. **vite-plugin-pwa**: SW-এর `PRECACHE` ও ভার্সন নিজে তৈরি হয়, ফাইলে হ্যাশ বসে।
  3. **ইভেন্ট-ভিত্তিক কনফিগ ফাইল** (`events/iqra-2026.json`: ফ্রেম, মাপ, রঙ, তারিখ, লিংক) — একই কোডে নতুন মাহফিল কনফিগ বদলে।
  4. **Cloudflare Worker + KV/D1**: ফ্রেম-তৈরির সংখ্যা, লাইভ কাউন্টার, একাধিক ইভেন্টের ড্যাশবোর্ড।
- **UI ফ্রেমওয়ার্ক (Svelte/Preact)** শুধু তখনই, যখন একাধিক পেজ, লগইন বা অ্যাডমিন প্যানেল লাগবে। Next.js এই কাজের জন্য অতিরিক্ত।
